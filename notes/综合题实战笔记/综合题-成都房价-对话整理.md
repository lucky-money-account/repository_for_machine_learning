## 2. 数据预处理为什么觉得难

**核心观点**：数据预处理是整个机器学习里最难、最经验化的部分（行业叫"脏活"，占真实项目 80% 时间）。前几章全是干净合成数据，第一次见真实数据觉得难是正常的。

**类比**：训练代码 = 炒菜（流程固定）；数据预处理 = 洗菜切菜（食材千奇百怪，临场处理）。

**其实只有 5 个固定套路**：

| 套路 | 一句话 |
|---|---|
| 正则提取数字 | `re.search(r'(\d+)室', s)`，找到取数字、没找到填 0 |
| one-hot | `get_dummies`，类别 → 一列 0/1 |
| 缺失值填充 | `fillna(中位数)` |
| 异常过滤 | 布尔掩码删行 |
| 标准化 | (x − 均值) / 标准差 |

**学习策略**：先抓流程（数据形状怎么变）、再抠细节；正则只学一个套路；一次只啃一个 TODO；卡 15 分钟看答案 → 合上自己写。

## 3. 为什么 clean_data 要先拷贝一份

`feat = feat_df.copy()` 是**防止把调用方手里的原始数据改掉**。

- `feat = feat_df` 只是给同一对象起了个新名字（贴标签），改 feat 就是改原对象；`copy()` 才是真正抄一份新的。
- 实验演示：不 copy 时，函数里 `feat['新列']=1` 会让外面的 `df` 也悄悄多一列。
- 本综合题里：`df[COL['单价']]` 是原始 df 的列（视图），指向原内存；不 copy 的话任何原地修改都会写回原始 df。
- **判断标准一句话**：函数里要"改"传入的 DataFrame/Series，先 copy；只读不写就不用。

## 4. 「不该清理原始数据吗」的困惑

**问**：训练时用的不就是处理好的数据吗，为什么不能直接清原始数据？

**答**：「训练用处理好的数据」和「保护原始数据」是两码事，不冲突。关键在**你会重跑**：

- 真实流程 = 改特征 → 重跑 → 看 RMSE → 再改。第一次跑就把 df 污染了，第二次就是在"洗过的菜上再洗"，结果不可复现。
- 训练用的 `X_raw` 本来就是 `clean_data` **返回的新对象**（副本）；原件 df 存档，供重跑、调试、追溯。
- 综合题第七步「拓展」就是来回改特征的场景，第一次跑就污染 df 会让后面的对比实验作废。
- 原则：**数据要清洗，但清洗的是副本；原件存档。**

## 6. num_examples = len(X_raw) 是干嘛的

就是"数一下有多少个样本"，返回一个数字，本身不处理数据。它存在的唯一原因是**后面两行要用这个数**：

```python
num_examples = len(X_raw)            # ① 数数 → 2000
idx = torch.randperm(num_examples)   # ② 生成 0..1999 的打乱索引
n_train = int(0.8 * num_examples)    # ③ 算 80% 是几行 → 1600
```

像切蛋糕前先数一数切成几块。

## 8. reindex 是什么

`reindex` = 按指定顺序/标签重排 DataFrame 的列（或行），缺的补上、多的丢掉。

这里解决 one-hot 预测的经典坑：训练时输入固定 128 列，新样本只有一个类别（如"北"），`build_features` 只生成 `房屋朝向_北` 一列。直接喂给模型会维度对不上 / 权重乘错特征。

```python
new_feat = new_feat.reindex(columns=X_train.columns, fill_value=0)
```

把残缺的列集合对齐回完整的 128 列，缺的补 **0**（one-hot 语义：缺失类别 = 该类别为 0，所以补 0 而非 NaN）。

类比：模型只认"固定 128 个插槽、固定顺序"；reindex 就是把新样本的 20 根线插到正确位置，剩下 108 个空槽补 0。

## 9. 能否用之前定义的函数规范化预测链路

**能，而且这才是规范写法。** 预测链路里手写的那行标准化：

```python
new_feat[NUM_COLS] = (new_feat[NUM_COLS] - train_mean) / train_std
```

就是 TODO 5 里 `norm()` 的逻辑重复。直接复用：

```python
new_feat = norm(new_feat)   # 复用 norm，删掉手写的那行
```

**为什么必须**：训练/推理特征一致性——手写两遍靠"记得它俩一样"，复用同一个函数靠"就是同一段代码，不可能不一样"。以后改标准化逻辑只改 norm 一处，训练和预测同时生效。

**更彻底的封装**：

```python
def predict_price(sample_df):
    feat = build_features(sample_df)
    feat = feat.reindex(columns=X_train.columns, fill_value=0)
    feat = norm(feat)
    x = torch.tensor(feat.astype('float32').values)
    with torch.no_grad():
        return net(x.to(device)).item() * y_std + y_mean

new_pred = predict_price(new_sample)
```

**边界**：`clean_data` 不要复用到单个样本——它做批量清洗+过滤异常，单样本不该被过滤、也没缺失要填。

## 10. 取对数后 loss 变 NaN

**根因：`log` 套错了对象。**

```python
y_hat = torch.log(net(X))   # 错：net(X) 可负 → log(负数)=nan
y = torch.log(y)            # 错：y 是标准化标签，可负 → nan
```

**正确思路**：模型去预测 log(价格)，取对数只作用在**原始价格**（恒为正）上。

① 数据侧（标准化之前）：

```python
y_log = np.log(y_raw)      # 先对原始价格取 log
y_mean = float(y_log.iloc[train_idx].mean())
y_std = float(y_log.iloc[train_idx].std())
y_train = (y_log.iloc[train_idx].values - y_mean) / y_std
```

② 训练侧（去掉 log）：

```python
y_hat = net(X)             # 直接输出，不再 torch.log
```

③ 预测侧（exp 还原）：

```python
new_pred = torch.exp(net(new_x.to(device)) * y_std + y_mean).item()
```

**为什么取对数有效**：房价呈对数正态分布（右偏），取 log 后接近正态、压缩离群豪宅的杠杆，线性模型更好拟合。比较取不取 log 时，都要用 exp 还原成真实"元/平方米"再算 RMSE。

## 11. loss 卡在 0.27 无法下降

**核心判断：0.27 是线性模型的天花板，不是没训好。**

- 标签标准化后方差 = 1；"只会猜均值"的 loss 是 1.0。loss 0.27 → **R² = 0.73**，已解释 73% 方差。
- 曲线从第 10 epoch 就平 = 收敛了，不是卡住。收敛后还在 0.27 = 剩余残差是**线性模型天生拟合不了的非线性**，换 lr/优化器都压不下去。

**1 分钟验证法**：换 `Adam(lr=0.01)` 跑 50 epoch，若还在 0.27 附近 → 铁证是能力上限。

**三个方向（按性价比）**：

1. **特征工程（线性模型内榨干）**：加 `建筑面积²`、`log(面积)`、交互项（面积×电梯、面积×市辖区）、房龄（挂牌时间→年份→2025−年份）、更多 one-hot（户型结构/建筑类型/交易权属）。特征 > 优化器。
2. **目标取 log**（见上节）。
3. **换 MLP（正解）**：房价非线性，线性模型天生拟合不了。第 4 章多层感知机就是为此而生——加隐藏层+激活函数能拟合任意连续函数。

**心态**：这题是"线性回归"综合题，R²=0.73 已合格；把房价真正压下去是 ch04 MLP 的舞台。卡在 0.27 这个体验，恰恰是第 4 章的引言。
