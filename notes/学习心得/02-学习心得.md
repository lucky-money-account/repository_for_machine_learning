## 一、广播机制：从"记住规则"到"看懂本质"

### 精华

- 广播 = "尺寸为 1 的维度复制拉伸"。逐维演示时：**谁那维是 1，谁就在那维被拉伸**；双方都不是 1 且不相等才报错。
- 各维拉伸**相互独立**，先后顺序只是讲解方便，最终形状唯一。
- 实际**不真复制内存**（用 stride 技巧"假装"重复），所以 `(2,3,4)+(4,)` 不会真的生成 24 个数的 b。
- 一维向量 `(4,)` 永远**右对齐到最后一维** → 视为 `(1,1,4)`。想对齐别的轴，手动 reshape 成 `(4,1,1)`。
- `keepdims` 的本质 = **主动制造一个"1"，控制后续广播的方向**。不是为了"能算"，而是为了"对齐到正确的轴"。

### 踩坑

- 报错只显示**第一处**冲突，但可能多维度同时冲突（如 `(2,3,4)+(2,3)` 的 dim1、dim2 都冲突）。逐维过一遍比只看报错强。
- 广播在两类运算的**作用范围不同**：
  - 逐元素 `+ - * /`：**所有维度**都广播
  - 矩阵乘 `@`：只有**批维（前导维度）**广播，最后两维必须严格匹配（内维相等）
  - 原因：广播的"1 拉伸"本质是复制，逐元素安全；矩阵乘要"消掉内维"，复制谁都会破坏数学定义。

## 二、矩阵乘法：`@` 是通用大门

### 精华

- `@` 是 Python 3.5（PEP 465）专门引入的矩阵乘运算符，因为 `*` 被逐元素乘占了。
- `dot`/`mv`/`mm` 是专用小门（1D@1D / 2D@1D / 2D@2D），`@`/`matmul` 是通用大门，全都处理还支持批量。

### 踩坑

- matmul 的 **1D 特殊规则**：1D 张量参与时先补 1 维 `(1,n)` 计算，算完**把补的维拿掉**。所以 `(3,) @ (3,2)` 结果是 `(2,)`，不是 `(1,2)`。
- **3D+ @ 2D 合法**：批维自动广播，`(2,3,4) @ (4,5)` = `(2,3,5)`，只要最后两维满足内维相等。
- `/` 是逐元素除法，和求逆无关。数学里没有"矩阵除法"，解方程用 `torch.linalg.solve`。

## 三、自动微分：backward 为什么必须标量

### 精华

- backward 的入口永远是**标量**。向量 y（n 维）对向量 x（n 维）的导数是 **n×n 雅可比矩阵**，`x.grad` 只能存 n 维、装不下 → 需要权重向量 v 把矩阵压成向量。
- `y.backward(v)` = 先算 `v·y`（加权求和成标量）再求导。`v = ones` 就是最朴素的"等权求和"。
- **偏导 vs "对应元素求导"**：偏导是每个输出分量 × 每个输入分量，天然是矩阵；"对应元素求导"（∂y_i/∂x_i）只在逐元素运算时成立，此时雅可比恰好是对角阵。

### 踩坑

- 四句锁死：**入口（backward 的量）必须是标量**；向量要加权求和降标量；自变量任意维；出口（`.grad`）永远和自变量同形状。
- `detach()`：返回**共享数据的视图 + 断开梯度**。两个易错点：① 它是视图，改它会动原张量（要独立用 `clone()`）；② "断开梯度"这个标记打在新副本 u 上，原 y 还在图里照常求导。
- `detach()` 为什么需要：① 省内存（自动求导贪婪记录一切）；② 语义（有些量只要数值不要梯度）；③ 转 numpy 前必须 detach；④ 算法需要"当常数"（GAN / 强化学习 target）。
- **梯度累积 ≠ retain_graph**：前者是"多张新图各求一次导、梯度累加"（模拟大 batch，不需要 retain）；后者是"同一张图求多次导"（多 loss 共享图，需要 `retain_graph=True`）。

## 四、计算图：记录真实路径

### 精华

- 计算图 = 前向运算的"**路线图 + 中间值账本**"。反向传播要沿图倒推链式法则，每个局部导数（如 dz/dy = 2y）都需要中间张量的数值，所以必须保留。
- **动态图（define-by-run）**：图跟着真实控制流走，if/else 没走过的分支根本不进图。所以 `f'(6)` 只对实际走过的分支求导。
- 图**用完即释放**（默认），这是省内存的策略；`detach`、`retain_graph` 都是"管理账本"的手段。

## 五、数据预处理：流水线 + 标识符

### 精华

- 预处理是**链式流水线**：读取 → 统计缺失 → 填充 → 独热编码 → 转 tensor。每步产物传给下一步，不能各自算完就扔。

### 踩坑

- pandas 自动把 `NA`/`null`/`NaN` 等识别为缺失值 `NaN`（read_csv 默认行为，Excel 不会）。
- `torch.tensor(DataFrame)` 报错 "could not determine the shape"：torch 不认识 DataFrame，要 `.values` / `.to_numpy()` 先转 numpy。
- **学号/ID 是标识符不是特征**：读入用 `dtype=str` 保留字符串（否则 `001`→`1` 丢前导零），然后 `drop` 掉。
- `get_dummies` **默认只碰字符串/object 列**，数值列不会被动。要编码哪个列，显式 `columns=['class']`。
- 混合 bool/float 的 DataFrame，`.values` 是 object 类型，torch 无法转换，要 `.astype(float)` 统一。
- 训练用 **float32**：pandas 数值是 float64，转 tensor 时指定 `dtype=torch.float32`。

## 六、张量形状思维

### 精华

- **括号层数 = 维度数**。1 维 = 一层括号 `[a,b,c]`（无行/列之分）；0 维 = 裸标量；2 维才有行向量 `(1,n)` 和列向量 `(n,1)` 之分。
- `sum(axis=几)` 消掉第几维：消 1 个轴少 1 维，消 2 个轴变标量。`keepdim=True` 才保留成 `(1,n)`。
- `reshape` 的 `-1` = 自动推断该维大小（元素总数 ÷ 已知维乘积），一个 reshape 只能有一个 `-1`。
- `permute` = 重排轴顺序（参数回答"新轴 i 来自原轴几"），是 `transpose`/`.T` 的通用版；返回视图，无原地版本。

### 踩坑

- `axis` 和 `dim` 是**同一个参数的别名**（PyTorch 官方叫 `dim`，为照顾 NumPy 用户加了 `axis`）。
- `help(函数名)` **不带括号**；带括号会先执行再 help。Jupyter 里 `?` 比 `help()` 更全。

## 七、概率：独立性的价值

### 精华

- HIV 双测试例子：为什么跑"测试 1 两次"不如跑"测试 1 + 测试 2"？因为组合两个测试的隐含假设是**条件独立**——已知状态后，不同测试的出错相互独立。同一测试跑两次结果**完美相关**，第二次零信息。
- **信息价值来自独立性**：重复 = 零信息，多样性 = 真增益。对应到深度学习：集成要用结构不同的模型，数据增强要多样化。
