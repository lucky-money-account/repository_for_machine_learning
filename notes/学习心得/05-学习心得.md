## 一、精华问题（本章最有价值的几个追问）

### 1. nn.Module / nn.Sequential 的本质是什么？

- **块 = 参数的容器 + forward 定义的计算**。`__init__` 定义子层（不传数据），`forward` 调用子层（传数据）。
- `nn.Sequential` 没有魔法：内部就是 `add_module(字符串名, 层)` + forward 时按 `_modules` 顺序调用。
- `net(X)` 自动触发 forward（`__call__` 机制）；`net[0]` 需要实现 `__getitem__`。

### 2. nn.Parameter 和普通张量差在哪？（本章核心认知）

- **只有 `nn.Parameter` 会被 `parameters()` 收集、被优化器更新**。
- `torch.rand(..., requires_grad=True)` 不算 Parameter——不会被收集、不会更新（踩过坑验证过）。
- `nn.Linear` 内部 = 两个 Parameter（weight/bias）+ 一个 `x @ w + b`——自己手写 LinearFromScratch 就复现了它。

### 3. 为什么网络要随机初始化？

- 全零初始化让同一层所有隐藏神经元**对称**（输入相同→输出相同→梯度相同→永远相同），N 个神经元退化成 1 个。
- 随机初始化 = 打破对称性，让每个神经元从不同起点分化成不同特征探测器。

## 二、「手写网络」5 步的具体体会

1. **手写一遍 = 看穿封装**：自己实现 MLP 类 → MySequential → nn.Parameter 手动注册 → 才真正理解 `nn.Linear`/`nn.Sequential`/`state_dict` 内部是什么。训练代码从"黑盒"变成"能自己写出来的代码"。

2. **踩坑踩出来的认知最牢**：
   - `_modules[block] = block`：键必须**字符串**（报 "can only concatenate str"）。
   - 忘写 f-string：`'layer{i}'` 字面输出。
   - `def` 写成了 `class`：继承 nn.Module 必须 class。
   - `X ** 0.5` 对负数开根号 → NaN 传染全网络（state_dict 里 layer5 全 NaN）。
   - `net.state_dict` 忘加括号 → 存了"方法对象"（先触发 weights_only 拦截，绕过后又报"Expected dict-like, got method"）。

3. **可视化/脚手架代码是"模板"不是知识**：meshgrid→stack→reshape→plot_surface 这套固定套路已封装进 `utils/visualization.py`（make_grid / predict_on_grid / plot_3d_surface / plot_true_vs_pred / plot_loss_history），以后一行调用。

## 三、综合题「MLP 模块化 + 保存加载」的体会

1. **模块化组装**：MLPBlock(10,64) → ReLU → Linear → state_dict 键名自然分层（`0.hidden.weight`、`0.out.weight`、`2.weight`）——键名反映网络结构，读 state_dict 就能看出网络长什么样。

2. **保存加载的正确姿势**：
   - 保存 `net.state_dict()`（只存参数），不存整个 `net`（结构靠代码重建）。
   - 加载：`net2.load_state_dict(torch.load('net.params', weights_only=False))`——**PyTorch 2.6+ 默认 weights_only=True**（安全加固），自己保存的文件要加 `weights_only=False`。
   - net2 结构必须和 net 完全一致（层序 + 维度），否则 key 不匹配。

3. **验证加载正确**：参数逐一 `torch.equal` 对比 + 前向输出对比——"参数一致 + 前向一致"双重确认。

## 四、典型问题（踩过的坑）

| 坑 | 现象 | 教训 |
|---|---|---|
| `_modules[模块] = 模块` | can only concatenate str | 字典键必须字符串，用 `add_module(str(i), ...)` |
| `torch.rand(requires_grad=True)` 非 Parameter | parameters() 找不到、不更新 | 可训练参数必须 `nn.Parameter` 包 |
| 忘写 f-string | `layer{i}` 字面输出 | `f'layer{i}'` 才插值 |
| `def` 定义继承类 | SyntaxError | 继承用 `class`，函数参数不能带点 |
| `X ** 0.5` 负值 | 全网络 NaN | 开根号前保证非负（abs/ReLU） |
| `net.state_dict` 忘括号 | weights_only 报错 → method 报错 | 方法是**调用**才加括号：`state_dict()` |
| `torch.load` 默认拦截 | UnpicklingError | torch 2.6+ 加 `weights_only=False`（可信文件） |
| 忘了 `self.` 访问属性 | NameError | 实例属性必须 `self.rand_weight` |

## 五、本章收获总结

1. **手写网络 4 步走通**：MLP 类 → MySequential（add_module+字符串键）→ nn.init（原地初始化）→ nn.Parameter 手动注册——`nn.Linear` 不再是黑盒。
2. **掌握保存加载**：state_dict 只存参数 + `load_state_dict` 加载 + PyTorch 2.6 的 weights_only 坑。
3. **工具库意识**：把固定套路（可视化、预处理、训练循环）封装进 `utils/`，分门别类，避免每次重写脚手架代码。
4. **第 5 章主线清晰**：①层和块（搭积木）→ ②参数管理（管零件）→ ③延后初始化（猜尺寸）→ ④自定义层（造积木）→ ⑤读写（存档）→ ⑥GPU（换引擎）。
